# v0.3.0 対話的挙動の手動確認チェックリスト

Linux バッチ検証(コンパイル+EditModeテスト)では確認できない、
実エディタでの対話的挙動の確認手順。GUI付きの Unity 2022.3 環境
(Windows 実機など)で一度なぞる。結果は本ファイルに追記する。

対象コード: `Editor/FontFixSettingsProvider.cs` /
`Editor/FontFixSettingsUi.cs` /
`Editor/Diagnostics/FontFixDiagnosticsWindow.cs`

## A. Project Settings ペイン

- [ ] Edit > Project Settings に「UITK Font Fix」が表示され、選択すると
      タイトル・説明・フォーム・Open diagnostics ボタンが描画される
- [ ] 検索ボックスに `font` / `cjk` / `japanese` / `monospace` を入れると
      ペインがヒットする(keywords の効き)
- [ ] CJK候補を1行1名で書き換え → Apply (this session) → ステータス行の
      Resolution 表示が変わる(開いている他ウィンドウは変わらない=仕様)
- [ ] Save to project →
      `ProjectSettings/Packages/jp.colloid.uitk-font-fix/settings.json`
      が生成され、ステータスが「saved to project (in sync)」になる
- [ ] Use package defaults → ファイルが消え、フィールドが既定値へ戻る

## B. 診断ウィンドウの編集フォールドアウト

- [ ] Window > UITK Font Fix > Diagnostics の「Edit configuration」を開き、
      候補を書き換えて **Apply を押さずに** Re-probe → レポートの
      Resolution が入力中の値で再解決される(Re-probe が保留編集を反映
      してから再プローブする、レビュー1c の修正点)
- [ ] Re-probe 後も Foldout は開いたまま・編集中のテキストが残っている
      (レポートのみ更新される)
- [ ] Save to project → Project Settings ペイン側を開くと同じ値が見える
      (フォーム部品共用の確認)

## C. ドメインリロード越しの適用

- [ ] settings.json がある状態でスクリプトを再コンパイル(またはエディタ
      再起動)→ 診断レポートの「Project settings file」が
      「present, in sync」になり、候補がファイルの値で解決される
- [ ] settings.json をエディタ外でテキスト編集(候補1件だけ残す等)→
      レポートが DIFFERS を表示し、ドメインリロード後に in sync へ戻る
