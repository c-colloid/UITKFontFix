# 設計ノート: READMEコードサンプルの記述スタイル

- 日付: 2026-07-31 / ステータス: 採用済み
- 発端: ユーザーレビュー「コードブロック内の説明が過剰。行ごとにコメントが挟まり、
  長文を機械翻訳する際に文が寸断されてノイズになる」

## 問題

改稿後READMEのQuick start/レシピ集は、コード各行に複数行の説明コメントを
付けていた。英語READMEを翻訳して読む利用者にとって、コメントがコードの折返しごとに
挟まる構造は翻訳結果を細切れにし、可読性を大きく損なう。

## 選択肢

| 案 | 内容 | 判定 | 根拠 |
|---|---|---|---|
| A | 現状維持(コメント充実がサンプルの自己完結性を高める) | 棄却 | 翻訳ノイズの実害が報告されている。自己完結性は散文+コードでも保てる |
| B | コメントを全削除しコードのみ | 棄却 | `// WRONG:`/`// RIGHT:` のような「位置が意味を持つ」目印まで失うと対比サンプルが成立しない |
| C | 説明はブロック外の散文へ、ブロック内は1行の位置目印のみ許可 | **採用** | 翻訳フレンドリー・コピペしやすい・情報は散文へ全量移設(欠落なし) |

## 決定

- README(および今後のドキュメント全般)のコードサンプルは案Cのスタイルで書く
- 規約として CLAUDE.md 4b 項に恒久化
- コード行自体は機能的に不変(コメント移設のみ)であることをサンドボックスでの
  実コンパイル+テストで検証してからコミットする
